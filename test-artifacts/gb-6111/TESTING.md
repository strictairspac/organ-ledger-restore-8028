# 勘误与证明效力 · 验收记录

验收环境不具备 Docker，改用等价本地栈：micromamba 安装 PostgreSQL 16.9 与 Redis 8，Python 3.11 虚拟环境安装 `backend/requirements.txt`，uvicorn 提供 API、`src.worker` 执行持久队列，前端用 jsdom 做渲染冒烟。

## 覆盖的业务规则

| 规则 | 验收方式 |
|---|---|
| 巡修组可更正测记、记错归属的维修单及随卷资料 | 操作员调用 `POST /cases/{id}/corrections`，非法资料与无差异勘误被 422 拒绝 |
| 勘误与复原并发时，排队批次按交单时资料完成 | 服务层构造 QUEUED 批次后勘误，再由 worker 按冻结快照完成，逐段 SHA-256 与勘误前同资料批次一致 |
| 勘误改变所选维修单或随卷资料，证明即刻失效 | 选中测记改动、工单改归属、闭包内琴体改名均使对应批次 `evidence_status=invalidated` |
| 改回原值不恢复效力 | 连续勘误还原原始资料，已失效批次仍为 invalidated，且不在新勘误的失效名单中 |
| 未受影响的证明照常签核 | 闭包外测记/琴体改动不失效；有效证明可签核，重复签核被 409 拒绝 |
| 失效批次不能再签核 | 对失效批次提交复核返回 409 |
| 已签核旧证明可原样下载 | 失效前后导出的 `digest` 与评审意见不变，导出仅多效力标注，且不含内部快照字段 |
| 失效批次重新执行才有可签核证明 | 勘误后新批次为 valid 并完成签核 |
| 勘误全程留痕、权限受控 | `case_corrections` 含版本/原因/结构化差异/失效批次；复核员勘误返回 403；审计含 correct_case、invalidate_evidence |

## 测试脚本与结果

脚本位于验收工作目录 `/tmp/acceptance`（项目仓库外，避免污染代码树）：

1. `e2e_corrections.py` — HTTP 端到端主流程，31 项，失败 0。
2. `e2e_edge_cases.py` — 损伤卷阻断证据、勘误后重跑、并发完成批次失效、导出字段，12 项，失败 0。
3. `test_queued_concurrency.py` — 排队批次快照与 worker 按旧资料完成的确定性并发，8 项，失败 0。
4. `test_impact.py` — 影响分析纯领域单测（闭包内外、参数截断、删除工单、顺序变化、差异结构），11 组场景，失败 0。
5. `web/smoke.mjs` — jsdom 渲染冒烟（失效标识、签核表单显隐、勘误表单权限、效力列），15 项，失败 0。

最近一次全量回归为干净库重置后顺序执行，合计 77 项检查全部通过。
